Implement $1.

1. **Read the spec fully before any code.** Find it via `brief/build/INDEX.md` (builds in `_BUILDS/`, addendums in `_ADDENDUM/`). If the spec references counsel gates or a parent build, read those sections too.
2. **GROUND FIRST — spawn the `grounder` agent** with the spec's concept list. **This is not a delegation to weigh against its cost — it is the precondition "have I looked before I write", which merely happens to be implemented as an agent.** Nobody asks whether reading the spec is efficient; this is the same category, and framing it as delegation is what makes it look optional. It is unconditional. What is NOT required is sitting idle: while it runs, read the spec's referenced sections, open the migration file you will amend, and draft the test fixtures. **No product code until its machinery map lands** — that half of the wait is load-bearing, because you cannot write against machinery nobody has told you exists. Extend what exists; duplicating an existing capability because nobody looked is the most expensive class of mistake here. Treat its collision and gap findings as blockers to resolve, not notes.
3. **Non-negotiables apply to every line:** `org_id` + RLS on every table, `audit_log` on every state change, `consent_log` for POPIA events, amend-forward migrations only (append §N BUILD_XX sections to 001–012; NEVER new numbered files; NEVER touch 007/008), all Anthropic calls through `lib/ai/client.ts`, every env read through `lib/env.ts`, `NEXT_PUBLIC_APP_URL` for every absolute URL.
4. **Sequence phases as spec'd, commit per phase** (commit-as-we-go — never trust an uncommitted working tree). Production-dark behind the gates the spec names. **Delegate the mechanical bulk** within a phase — a codemod, a migrate-N-sites sweep, a rename — to the `implementer` agent **in this checkout; never pass `isolation: "worktree"`** (E10: a worktree is cut from `origin/main`, so on a feature branch the agent transforms a different tree from yours and its green gate proves nothing about yours). Spawn it with the transform and its scope, and **in the same breath start the next concrete thing: draft the next phase's ESLint rule and its two probe fixtures while it runs.** If the sentence after the spawn ends in a full stop, the main session waits — measured, and it cost roughly 2× wall-clock in the cells where it happened. Keep the judgment sites and the SSOT/rule design in the main session.
5. **Where the scope splits, run the agents CONCURRENTLY — issue them in ONE message.** Agents dispatched in separate messages are waited on one at a time; several tool calls in a single message overlap. Measured on the E17 arm-C cells: eight agents, eight separate messages, **peak concurrency of one** — 92.9 agent-minutes stretched across a 206-minute span. Part of that was correct and must stay serial: a verify→fix→re-verify chain cannot be parallelised, because walk N reads the tree walk N−1 changed. The rest was not. When the work genuinely splits — several reviewers each taking a different dimension of one diff, censuses over unrelated patterns, grounding two subsystems, an `implementer` sweep over files another agent will not touch — send them together. Judge it by scope overlap, not by count: two agents on disjoint files are safe at any size, two on the same file are wrong at any size.
   **One hard boundary, mechanical rather than stylistic: only ONE process may run the test gate at a time**, agents and this session included. `npm run check` writes `node_modules/.vitest-count.json` and reads it back in the same command, and `node_modules` is a junction shared by every worktree and the main checkout — so two concurrent runs race on one physical file. A truncated read fails the gate for no reason; worse, a partially-collected run that reads the other's complete report goes green, which is the exact failure `check-test-floor.mjs` exists to catch. Fan out the reading and the analysis; keep the gate serial.
6. **Deviations are allowed but never silent.** Each deviation from spec gets flagged in the report with reasoning — the spec author decides whether it stands.
7. Finish with `/walk`, then `/wrap`.
